# frontend-mvp 변경 통합

대상: `feat/frontend-mvp`의 `40b62c7`(사진 전송 보강), `01c5a8b`(조기 결정·홈·목표 상호작용). 적용 위치: 기존 HTML UI와 APK API 흐름을 사용하는 `apklike`.

| 원본 변경                         | apklike 적용                                                                                  |
| --------------------------------- | --------------------------------------------------------------------------------------------- |
| Expo 58 File + expo/fetch 전송    | 이미 적용된 방식 유지. 파일 존재 검사, 본문 수신까지 타임아웃 유지, 원인 오류 보존을 추가     |
| 이미지 crop URI 변환              | 기존 mapper와 실제 APK 초안 모두 적용. JPEG/PNG/WebP 검증 및 기존 JPEG 저장 데이터 호환       |
| 진행 중 Buy·Bye, 종료 후에만 보류 | 실제 `observation.tsx`에 반영. 서버에 확정 요청하고 성공했을 때만 홈으로 이동                 |
| 홈의 미연결 알림 종 제거          | 종을 설정 아이콘으로 변경. APK의 알림 설정·기록 안내 진입은 유지                              |
| 목표 달성 원 클릭 재생 제거       | HTML 목표 달성 원은 이미 클릭 불가. Confetti의 replay 인터페이스와 이전 문구도 정리           |
| 기존 로컬 상태 전이 및 테스트     | 새 Buy 허용 규칙 반영. 활성 앱의 원본은 계속 서버이며 로컬 계산으로 서버 물품을 덮어쓰지 않음 |

기존 `702685a`는 공통으로 포함된 커밋이므로 중복 적용하지 않았다. 화면 파일 전체를 복원하지 않고 실제 활성 HTML 화면에 변경 의도를 옮겼다.

`40b62c7`의 도구체인 overrides/ESLint 호환 래퍼는 그대로 덮어쓰지 않았다. 이 브랜치는 ESLint 9와 기존 SDK 의존성으로 검사하고 있으며, 업스트림의 ESLint 10용 래퍼는 명시적인 `@eslint/compat` 개발 의존성도 추가하지 않은 상태다. 현재 검증된 lockfile 및 직접 선언한 `expo-file-system` 의존성을 유지했다.

**백엔드는 수정하지 않았다.** 조기 Bye는 프론트 준비만 완료되며, 현재 서버에서는 `409 SIMULATION_NOT_COMPLETE`가 올 수 있다. 실패하면 완료 처리·로컬 가상 적립·물품 삭제를 하지 않는다. 후속 백엔드 작업은 [조기 Bye API 수정 사항](backend-early-bye.md)을 따른다.

## 검증

- TypeScript, ESLint, Jest 140개 테스트(18개 suite) 통과.
- Android/iOS Hermes 및 Web export 통과.
- 브라우저 통합 테스트 통과: 사진 3건 등록·재실행 보존, 게스트 1회 발급, 조기 Bye 409 후 물품·기기 답변 유지, 서버 허용 시 같은 요청으로 확정 및 홈 이동. 총 94개 API 요청을 테스트 응답으로 처리했다.
- 실제 서버 데이터를 변경하지 않았고, Android Expo Go 실기기 및 배포 서버의 조기 Bye 성공은 아직 검증하지 않았다.

이번 통합은 로컬 `apklike`에만 저장하며 GitHub push는 수행하지 않는다.
